go synctest

2025-10-18 · 创建于: 2025-10-18 · 1 min · 90 words
 ·  CS
 ·  Golang , 2025

长期以来，异步逻辑的单测都令人十分的头疼，我们一般通过使用sleep来碰运气，但是sleep又会面临一个问题，就是简单的单测耗时却大量增加，而且脱离本地环境在容器环境编译时，cpu调度不上，这简直就是灾难。

救星来啦，testing/synctest包终于来了(1.25版本)。

有两个方法，synctest.Test 和 synctest.Wait

在synctest.Test里，时间是假的，可以理解为，这里面的逻辑，梳理好先后顺序后则按顺序执行，中间的等待时间全部被跳过了。如下的例子，这里不会真的sleep一个小时，测试函数可以瞬间完成。

func TestXXX(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		time.Sleep(time.Hour)
		fmt.Println("synctest sleep done")
	})
}

synctest.Wait则能够帮助等待此前的所有goroutine都进入稳定状态(要么执行完要么阻塞住？)。如下的例子，routine1 routine2都执行完毕，routine3阻塞在sleep，才继续执行synctest.Wait()之后的逻辑。

func TestXXX(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		fmt.Println("start")
		go func() {
			fmt.Println("goroutine 1 start")
			fmt.Println("goroutine 1 done")
		}()
		go func() {
			fmt.Println("goroutine 2 start")
			fmt.Println("goroutine 2 done")
		}()
		go func() {
			fmt.Println("goroutine 3 start")
			time.Sleep(time.Second)
			fmt.Println("goroutine 3 done")
		}()
		synctest.Wait()
		fmt.Println("end")
		time.Sleep(time.Second * 2)
	})
}

输出：
start
goroutine 3 start
goroutine 1 start
goroutine 1 done
goroutine 2 start
goroutine 2 done
end
goroutine 3 done
